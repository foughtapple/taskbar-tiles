## Taskbar Tiles 0.7.7

### Shortcut reliability

An unrelated recoverable UI error used to turn off Alt+Tab handling for the rest of the process lifetime. The saved setting remained enabled, so restarting appeared to repair it. Separately, Windows may silently remove a low-level keyboard hook after a timeout; a stored nonzero hook handle is not proof that the hook is still active.

- Keep the saved Alt+Tab preference after a recoverable menu error. Repeated faults use a visible ten-second cooldown rather than permanently disabling the shortcut.
- Keep keyboard callbacks short: classify the combination and post a bounded native message; no UI or Shell work is run on that callback.
- Renew the registration during idle periods, never while keys are held. Recover a stopped hook thread and request repair after resume. Silent removal can still mean a missed shortcut until the next idle renewal, at most approximately one minute when keys are released.
- Add **Settings > Startup & tools > Repair shortcut handling / Show shortcut status / Open shortcut diagnostics**, plus **tray > Shortcut health / repair**.
- Opening the installed executable again signals repair of the existing resident instance. The X-Mouse `--toggle` command and Ctrl+Alt+Space remain available independently of Alt+Tab interception. An explicitly disabled Alt+Tab preference stays disabled.
- Record bounded local runtime/registration/error diagnostics, without recording individual keys or typed text. This does not install a background service or promise recovery after every process crash or system-level restriction.

### Click-away and drawing

Include the previously prepared 0.7.6 outside-click repair on top of the published 0.7.5 font/drawing repair. Outside clicks are observed without consuming them, including when a topmost popup did not receive foreground activation. Settings still discards unapplied edits on outside dismissal; explicit Apply remains saved.

### Touch screen monitor support: compatibility-test milestone

**Automatic touch/pen return is not implemented or enabled in this release.** The requested first milestone is a non-interfering input test before attempting global focus/cursor return. A primary pointer's promoted mouse events cannot establish whether all fingers are up, whether a pen is still hovering, or whether a saved foreground window was captured before touch changed it.

Open **Settings > Touch screen monitor support**, select the touchscreen in the monitor diagram, then choose **Open input test**. The test shows native touch/pen events, contact count, pen range/pressure inside its own canvas, passive promoted-source event counts, and whether background digitizer reports are available. Those are observations, not a certification of cross-application input support. Copy the report after testing touch, two-finger holds, pen strokes/hover, another app and the physical mouse. Test Surface/spacedesk and Apollo separately.

While the diagnostic is open, ordinary Alt+Tab is temporarily left to Windows and Settings click-away is temporarily paused so you can test another app. Closing the test restores those preferences. It closes after five minutes, never restores/moves focus or cursor automatically, never injects or replays drawing, and does not log coordinates, raw HID payloads, window titles, typed text or screenshots.

### Update

Use **Settings > Updates > Check for updates... > Download & install**. Install over the current version without uninstalling. Existing favourites, label sizes, monitor layouts, startup choice and X-Mouse command are retained. No registry security relaxation, certificate bypass or machine-wide hook setting is applied.

### Validation and limits

Publication requires compilation, helper tests, real-menu paint tests, native outside-click and topmost tests, native keyboard registration removal/recovery tests, app-managed launch fixtures, actual updater HTTPS/download/checksum verification and installer lifecycle tests. Touch source/interop checks do not substitute for tests on an actual touchscreen driver. The user's exact intermittent failure has not been reproduced from a local log; the concrete disabled-hook path and removal/recovery handling are tested separately. Installer unsigned; SHA-256 verifies download integrity, not an independent publisher identity.
