## Taskbar Tiles 0.9.1

### Reopen Steam and app UI instead of a background helper

A window's rendering process is not always its launcher. The fallback inventory could offer a helper executable directly, while launching a tray-resident client without an explicit show request could leave its UI hidden. These are concrete gaps in the previous code; the reporter's exact launch has not been reproduced without a local launch log.

- For an ordinary Steam app entry, resolve the registered Steam installation and send one `steam://open/main` request through that client executable. Steam decides whether it starts or reuses the already-running client. Matching recognizes that installation's Steam UI helper when the newly shown window lacks an AppUserModelID.
- Never guess from the tile's friendly name. A different installation, unrelated executable, conflicting profile identity or ambiguous hosted window is not selected.
- A taskbar-origin shortcut containing only the startup `-silent` switch can show the main UI; its file is not edited. Explicit favourite arguments, game launches, account/login commands and other custom switches remain unchanged. No process is killed and no Steam setting is modified.
- Prefer paired `System.AppUserModel.RelaunchCommand`/display-name metadata from an eligible window over running its renderer executable. Preserve executable/argument separation and profile identity; reject ambiguous unquoted paths and invented command-interpreter routes.
- In the compatibility fallback, invoke Explorer's exact app-button default action where available. If that action is unavailable before dispatch, the physical fallback is a normal click, not Shift+click. A physical click still requires fresh visible/unobstructed geometry. No forced taskbar reveal, hidden-coordinate click or retry after an uncertain dispatched action.
- Apps with verified ordinary launch targets still follow their own single/multiple-instance settings. This is not a universal emulation of every application's private tray protocol.

### Preserve the other work

The Stream Dock modules are being developed on `feature/stream-dock-module`; this repair does not alter or merge that branch. Existing switcher layout, auto-hide discovery, Recent apps, Search, touchscreen settings, shortcut recovery, launch outcome tracking and secure updates are retained.

### Update

Settings > Updates > Check for updates... > Download & install. Choose 0.9.1. Do not uninstall first. Favourites, history, startup choice, X-Mouse paths and preferences are preserved.

### Validation and remaining limits

Release gates include compilation/helper tests; a native cross-process UI Automation default-action test; a hidden-to-visible fixture app observed by the real launch tracker; duplicate-dispatch protection; Steam installation/argument/helper-identity policy checks; all existing rendering, outside-click, topmost, launch, touch/shortcut, launcher/search/history, HTTPS/checksum and installer lifecycle tests.

The native fixture is not an actual Steam login or Windows 11 taskbar/tray installation. The reporter's specific desktop and Stream Dock hardware are not reproduced by CI. The installer is unsigned. If a particular app still does not show, its local launch diagnostics are needed; ambiguous windows are not forcibly exposed.
