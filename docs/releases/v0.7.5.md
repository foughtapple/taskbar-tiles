## Taskbar Tiles 0.7.5

### Fix: white menu with a large red X

The screenshot is consistent with Windows Forms' failed-paint placeholder. A concrete resource-lifetime bug was found: assigning a new Font with identical values can leave the previous Font reference installed on a control, while the old menu-open/preview path then disposed that previous object. Restarting discards that damaged in-memory state. The exact exception on the reporter's PC was not supplied, so the screenshot alone cannot establish which draw call failed.

- Reuse fonts on unchanged menu opens; explicitly rebind controls before retiring replaced fonts.
- Restore actual live font references and complete live layout after a Settings preview, rather than leaving draft drawing rectangles behind.
- A failed optional icon uses a neutral fallback, not a blank whole window. Invalid images are not retried every frame.
- Contain menu paint errors before they reach Windows Forms' permanent error state. Attempt a bounded repair, then dismiss safely if repeated rendering still fails. No restart, settings reset, application launch or window move is used as recovery.
- Add tray actions **Repair menu rendering** and **Open rendering diagnostics**. The new bounded local log records exception type, stack method names, version and graphics-resource counts, not app titles, search text or click coordinates.

### Fix: clicking away does not close the menu

A topmost window can be visible without ever obtaining activation, so a Deactivate event alone is insufficient. The menu now also observes outside left/right/middle mouse-down events and closes without consuming the click. The same action still reaches the app or desktop underneath.

- Respect the existing **Close the menu and Settings when clicking outside** preference.
- Ignore clicks in the menu, embedded Search, owned dialogs and controls.
- Use session IDs so a delayed old click cannot close a newly opened menu. Hide/selection/shutdown disarms observation; it cannot reopen a dismissed popup or fight app activation.
- Settings and its owned dialogs keep the discard-on-outside-click behaviour. Unapplied changes are discarded; an explicit Apply remains saved.

### Update

Use **Settings > Updates > Check for updates... > Download & install** for 0.7.5. Do not uninstall first. Existing sizes, favourites, app-managed instance behaviour, monitor layouts, X-Mouse bindings, topmost and secure-updater fixes are retained.

### Validation and limitations

Release publication requires Windows compilation, helper regressions, native repeated equal-font/preview restoration tests, injected paint and disposed-icon failures, actual outside-click tests against a separate nonactivating fixture process, existing topmost and launch tests, production updater HTTPS/download/checksum verification and installer lifecycle smoke tests. These tests do not reproduce the reporter's exact display driver/session or prove the original exception's stack. The installer remains unsigned. No Windows security settings are changed.
