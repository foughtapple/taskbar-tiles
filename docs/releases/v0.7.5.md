## Taskbar Tiles 0.7.5

### Fix: menu turns white with a red X after working normally

The screenshot is consistent with Windows Forms latching an exception during custom painting; DWM window thumbnails can remain visible independently. The screenshot alone does not identify the original exception.

A concrete font-lifetime defect was found in repeated-open and settings-preview code: Control.Font compares font values, so assigning an equal new Font can leave the old object attached. Disposing that old object can then break a later draw. This release fixes that ownership path rather than just hiding the error.

- Keep an explicitly owned set of menu fonts and reuse it when sizes/DPI are unchanged.
- Rebind both the menu and filter control by reference before disposing replaced fonts. Restore live bindings before disposing a settings preview's temporary fonts.
- Keep fonts alive until dependent child controls have been disposed.
- Give an invalid icon a neutral fallback instead of breaking the entire menu.
- Contain managed drawing errors before the framework enters its persistent red-X paint state. Rebuild fonts/layout asynchronously, with at most two automatic attempts per menu opening.
- A persistent failure shows a dark recovery message. F5 or tray **Refresh menu graphics** retries; Esc/outside dismissal still closes the popup. A queued recovery never reopens a dismissed menu or changes settings.
- Add tray **Open rendering diagnostics**: local version, drawing stage, exception type/stack and graphics-resource count. No screenshots, window titles, search text or command arguments are recorded by this log.

### Update

Use **Settings > Updates > Check for updates... > Download & install**, or install **TaskbarTiles-0.7.5-Setup.exe** over your current copy. Do not uninstall first. App-managed launches, exact-window switching, topmost behaviour, favourites, sizes and X-Mouse settings are retained.

### Validation

Release publication requires the Windows build and existing helper/native launch/topmost/updater/installer tests, plus a rendering regression using the actual menu paint and preview methods with hooks, tray, inventory and launch workers disabled. The regression reproduces the old equal-font/disposal failure, then checks repeated paint/preview cycles, text/scale changes, an invalid icon, injected managed drawing errors, bounded retry and safe dismissal.

These tests cannot prove which exception occurred in the supplied desktop screenshot. The new local log captures details if another cause remains. The installer is unsigned; SHA-256 verifies download integrity, not an independent publisher identity.
