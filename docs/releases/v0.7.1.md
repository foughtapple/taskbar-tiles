## Taskbar Tiles 0.7.1

### Fix: an app opens but its window is not recognised for zone placement

- Resolve the exact launched shortcut/AppsFolder item's executable and app identity independently of its icon. A Windows-generated taskbar grouping key or executable path is no longer treated as a conflicting explicit app/profile ID.
- Resolve supported packaged-app frames through their hosted CoreWindow identity while retaining the top-level owner/PID for safe placement.
- Refresh startup identity every 500 ms. Never infer identity from a friendly window title, executable filename alone, or an unrelated foreground app.
- Preserve explicit browser-profile conflicts, PID/start-time checks, new-window requirements and stable-window waits. Conflicting or ambiguous identities still require your choice.
- If the safe candidate list is empty, the manual chooser now shows all eligible open windows immediately and explains why. Nothing moves until you select it.
- Record version, identity kind/fingerprint, executable basename and rejection reason in local launch diagnostics. No window titles, command arguments or full user paths are added to those records.

### Updates in Settings

**Settings > Updates > Check for updates...** checks GitHub immediately and offers **Download & install** for a newer published release. The existing tray and Startup & tools entry still work. Downloads are SHA-256 verified and installation requires your action; there is no silent updating.

### Install / update

Use the existing app's **Check for updates...** command, or download **TaskbarTiles-0.7.1-Setup.exe** below and run it over your current installation. Do not uninstall first. Settings, favourites, sizes and X-Mouse commands are preserved.

### Verification

Published only after Windows compilation, deterministic helper tests and installer install/upgrade/uninstall tests pass. New regression tests cover generated-vs-explicit IDs, exact executable matching, profile separation, hosted frames and privacy-safe diagnostics. See build-info.json for the tested commit and workflow run. CI does not exercise your actual desktop, specific app or multi-monitor session; an unrecognised app can still require manual selection.

The supplied log did not name the app or record its identity, so it cannot establish which identity lookup failed on that desktop. This release fixes demonstrated gaps in the matching code and makes future failures diagnosable; it does not claim a live reproduction of that particular launch.

**Unsigned installer.** The checksum verifies integrity, not an independent publisher identity. Do not disable Windows security to install.
