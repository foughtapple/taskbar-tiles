## Taskbar Tiles 0.7.2

### Fix: updater reports "Could not create SSL/TLS secure channel"

The release build used CodeDOM and omitted the .NET Framework target attribute that MSBuild would normally generate. Requiring the 4.8 runtime in app.config was not sufficient to select the intended newer framework networking defaults.

- Declare the .NET Framework 4.8 target explicitly for both build paths.
- Enable OS-selected TLS and strong cryptography in this application's configuration. No machine-wide registry changes, obsolete-protocol fallback or certificate-validation bypass.
- Keep HTTPS-only trusted-host checks and SHA-256 verification for installer downloads.
- Add clearer TLS/certificate error messages and an always-available **Browser download** button.
- Preserve all 0.7.1 window-placement fixes, the Settings Updates tab, settings, favourites, startup preference and mouse shortcuts.

### Updating from an affected version

An updater that cannot make its HTTPS connection cannot fetch its own repair. Download **TaskbarTiles-0.7.2-Setup.exe** below in your browser and run it normally over your current version. **Do not uninstall first.** No publishing scripts, Git commands, administrator mode or security changes are required.

After installation, open **Settings > Updates > Check for updates...**. It should now connect to GitHub; a later published version will enable **Download & install**. A current installation does not offer a redundant reinstall.

### Verification

Publication requires Windows compilation, offline runtime/security regressions, an online test of the **actual compiled executable** fetching GitHub release metadata and downloading/checksum-verifying a released installer, plus install/upgrade/uninstall smoke tests. The network test deletes its download and never executes it. See build-info.json for the run and tested commit.

These checks cannot certify this user's network, proxy, certificates or clock. Those can independently prevent TLS; the app continues to fail securely and offers a browser route rather than weakening validation.

**Unsigned installer.** SHA-256 detects corruption, not an independent publisher identity. Do not disable Windows security to install.
